1. EAGER
	1. 연관 객체를 즉시 등록
	2. 스키마 정의 과정에서 이러니까 조회 케이스별 다른 정책 적용 어려움
2. LAZY
	1. 연관 객체는 프록시로 두고 실제 접근 시 조회
	2. 두 가지 옵션이 있어서 경우에 따라 취사선택 가능
		1. Fetch Join
			1. 조회 시 연관 객체도 로딩
			2. 메모리 사용은 올라가겠지만 연관 객체가 필요한 경우에 사용
		2. Join
			1. 조회 시 조회 대상이 아닌 객체는 영속성 컨텍스트에 등록 안 함
				1. 예) `select p from Player p join p.team t;` <- p 만 등록
				2. 예) `select p, t from Player p join p.team t;` <- p, t 등록
			2. 근데 sql 쿼리 상으로는 join 날림
			3. 연관 엔티티를 프레디키트로 사용할 때 사용
